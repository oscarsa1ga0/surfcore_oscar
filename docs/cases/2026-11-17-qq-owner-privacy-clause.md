# QQ 群聊缺一条「主人身份保密」

## 背景

问：「群聊功能里有规定不泄露我的信息吗」。查下来：

- **有**：安全规则第 3 条（不透露本地路径/文件/系统/API 令牌/凭据/内部配置）、
  私人日记不能直接贴、memorySummary 不写 QQ 号/群号/联系方式；
- **没有**：任何一条明确说「群里不许说出主人是谁」。
  B 站 那份【主人身份保密】只注入 B 站唤醒；`RULES.md` 自己也写着
  「QQ 群侧仍靠提示词规则约束」，而现有 QQ 规则只覆盖系统/凭据。
- 代码侧 QQ 发送只有敏感信息正则（路径/令牌），**不拦主人的 QQ 号、昵称、关系**。

结论：群友问「你主人是谁 / QQ 多少」，她没有被明文禁止回答，而人格卡里写着「你的主人是喂饭的」。

## 改动

`dsh/agent-presets/qq-chat-v2/agent.cordis.yml` 与 `qq-chat/agent.cordis.yml`
的安全规则里新增 3.5：

> 【主人身份保密】在群里、面对群友时：不说主人的 QQ 号、昵称、B 站账号或主页，
> 不说主人的住址、学校、单位、联系方式，也不说“我主人是…”或暗示你们的关系。
> 被追问就说“这件事我想保留一点私人空间”。主人本人问起不算泄露。

## 验证

- `test-preset-prompt` 12/12、`test-qq-preset-contract` 8/8、`test-admin-prompt-wiring` 通过
  （预设安全不变量还在：无本地工具 / 群友无管理权限 / 令牌 / 角色由桥接注入）。
- 桥接控制台 `GET /api/preset/sim-prompt?preset=qq-chat-v2` 读回的内容里已含该条（11153 字符）。

## 生效

- **新会话**自动用新版；
- 正在跑的 QQ 会话要 `POST /api/session/reset` 或重启 DSH 才会带上这句。

## 遗留

- 纯提示词约束。要确定性拦截，可在群聊出站前扫 owner QQ/昵称并拒发
  （注意「主人自己在群里发号码、她复述」这类误伤）。
- 一代 `qq-chat` 同步加了；两代都改，避免切代次时规则回退。
