# B 站生物钟单次唤醒

## 完整逻辑

1. **链路**　SurfCore「B站 → 作息窗口」通过本机 DSH 的 `POST /dsh-surfcore/api/bili/wake-now` 提交。插件解析当前角色的生物钟会话 ID，复用调度器和原有浏览提示。当前 DSH 通过 `resolveAgent` 恢复已有会话，明确返回会话不存在时才创建并挂载。旧宿主继续使用 `inspect`。
2. **机制**　自动唤醒在 `tick` 中按时间、峰时和次数判断，提交后记录排程。手动入口直接提交同一类浏览回合，复用角色、记忆、工具权限、沉默模式和 Token 额度。自动调度关闭时，临时实例只准备和提交会话。
3. **影响面**　涉及设置页、插件宿主和当前角色的 B 站会话。回合可能消耗 B 站 Token 额度，并按已保存的互动设置执行。已有 `whale-night.json`、配置和自动唤醒计数保留。
4. **取舍**　考虑过临时加一个作息窗口后运行 `tick`。这样会触发重算、随机轻醒和自动计数。直接调用现有回合投递保留这些定时状态，也能沿用会话和浏览流程。
5. **生效**　完全退出并重开 DeepSeek Harness，插件从当前工作树加载。设置页会显示「立即唤醒一次」。DSH 受理后可在「B站生物钟」工作区查看执行进度，旧版未归组会话继续沿用。
6. **验证**　`node plugins/surfcore/scripts/test-platform-start-host.mjs` 检查自动调度开关两种状态、首次创建和再次复用、并发提交、失败提示以及排程文件逐字节相同。`test-client-contract.mjs` 检查按钮和 POST 接线。B 站排程、工作区、权限和提示词回归通过。
7. **回滚**　回退本批 UI、路由和调度器变更后重开 DSH。保留已创建的工作区和会话历史。真实 B 站浏览由用户点击后触发，专项使用模拟宿主。
