# 鱼姬之家私聊可靠性与双向媒体

本机安装基线是 macOS 分支的 2d41db2，加上当时工作树里的头像、看图、恢复和计费改动。修复在独立的 `fix/web-chat-reliability` 工作树完成。

## 消息与回合

浏览器为同一次发送保留请求 ID。服务器事务保存消息、附件、回合，并使用含引用和附件摘要的校验值验证重试。合批及等待期间读到的补发消息依附主回合，一起结算。首答等待先补读新消息再检查静默。主动回合从自身提交时的游标起算。

已提交的回合重启后按原请求 ID 对照 DSH 事件。结果不确定时在对应气泡显示核对提示。可确定未提交的失败才提供重试，且重试请求复用原附件，避免双击或多个标签页复制回合。只从发送工具发布气泡，普通模型输出留在 DSH。主动搭话按实际发布的回执结算，内部备忘只供目的统计。晚点回来与当前回合收尾一起落库，DSH 再启动后可以接着执行。

## 网页和媒体

SSE 分页补齐新消息，普通重连继续用原游标。浏览历史时保留位置，新消息可以从「回到最新」入口查看。旧消息的回合状态和对应历史页一起返回。纯图片、表情和语音都有引用预览。

发送栏支持双向文本、图片、表情、录音或音频文件和拍一拍。语音附件可以播放，也可以附一句文字。要让鱼姬理解没有附言的语音，在 SurfCore 的鱼姬之家页面指定本地 `whisper-cli` 和多语种模型路径。转写先用配置的 ffmpeg 提取单声道音频，临时文件在本机处理后清理。未配置或失败时，界面提示鱼姬只能读附言。QQ 快照和新收藏共用目录，语义匹配也读同一份数据。

补读聊天和签发看图凭证都需要当前已接收的网页回合。MCP 通过本机网关使用限时单次凭证读取已授权资源，宿主在返回前重新检查回合和角色。启动新会话要求 DSH 已加载 Web 预设，旧会话地址保留。浏览器聊天历史仍由同一 SQLite 存储提供。

## 配置和计费

桥接、网页、桌宠和通知共用 QQ 配置中的目的载体。停用、重启网页不会覆盖网页本地配置。主动搭话开关与收取主人通知的目的地分别判断。网页 Token 单独显示并计入总额，继续使用现有的「其他」渠道额度。

## 取舍与影响

沿用 DSH 调度和 SQLite 存储，给发送和结算补齐持久记录。这条路线只涉及浏览器、插件宿主和看图 MCP，旧聊天文件可原地使用。新建一套聊天/队列服务需要迁移历史，还要重新接线调度、配对和模型工具，成本和回滚范围都更大。

## 验证与回滚

- `node plugins/surfcore/scripts/test-web-chat.mjs` 验证合批、失败联动、重启核对、内部文字隔离、看图凭证、表情和语音消息。
- `node plugins/surfcore/scripts/test-web-browser.mjs` 验证未收到发送回执时复用 ID、重连保持历史位置以及旧消息失败提示。
- 表情、语音、工作区、预设、客户端和 Token 额度专项通过。全仓审计 136/164，基线 135/163，共有相同的 28 项既有失败。桥接回归所需的回环端口在当前环境返回 EPERM。
- 安装后需要完全退出并重开 DSH。检查旧对话还在、录音权限和真实浏览器播放，再用一条普通对话核对模型看图及主动消息。长等待受 DSH 的实际工具时限影响。
- 回滚前结束当前网页回合，回退源码补丁并重开 DSH。SQLite 的老表结构仍可读取，新加入的关联字段、录音气泡和预约返回只由新版完整处理。

## 发布交接

`fix/web-chat-reliability` 修复网页发送、回合恢复、历史、主动状态、看图隔离和 Token 统计，并补齐发送栏的双向媒体。现有安装若已注册 `mcp-web-images`，更新后重开 DSH 即读取新版 MCP。仅对缺少该注册项的安装重新运行配置脚本。真实浏览器、模型和本地语音转写的验收仍需在本机完成。
