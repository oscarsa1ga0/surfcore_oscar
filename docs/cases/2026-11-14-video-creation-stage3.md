# 视频创作阶段三：投稿、审核和作品记忆

## 现象与环境

本机 DSH 的安装链接对应 `feat/video-creation@76d6105`。鱼姬已能剪片和审片，`video-upload` 是占位命令，管理页投稿确认返回 501。第三阶段在独立工作树实现。macOS 上使用 DSH 自带的 Node 24 测试。

## 完整逻辑

- **链路。** 鱼姬使用 `video-upload` 预检或排队。管理 API 允许用户确认当前账号和版本。后台执行器读取角色独立的 SQLite 队列，采用扫码凭据请求 B 站。审核公开后同时给作品记忆和已配置的报备通道产生事件。
- **机制。** 草稿、确认、自主档复用稿件包。批准绑定角色、账号、版本、MP4 与封面摘要、元数据和素材授权。上传凭据只存账号目录的限权文件，公开请求与 UPOS 请求使用各自凭据。分片按照已确认的序号恢复，网络错误按退避重试。最终投递先持久化提交意图，丢回执后按媒体 ID 查稿。人工提供的 BV 也需匹配媒体。改分区、换素材或编辑后用新稿件包，既有受理稿件继续跟踪。最终投递与日常动态、自由动态、分享和专栏使用账号级冷却时钟。
- **影响面。** DSH 插件宿主、命令行工具、B 站的账号和公开稿件，以及既有叙事和向量记忆链。第一次回读必须确认原生 AI 创作声明及分区属性，才能放行同账号同分区的自主请求。审片失败、素材未准许公开、敏感账号信息、摘要变化和账号不一致均有错误及下一步。若需要彻底隔离拥有完整执行权限的模型，使用受限会话设置。
- **取舍。** 网页适配复用扫码账号，降低上手成本。平台字段可变，需要首稿在实际创作中心验证。开放平台 API 有稳定文档，代价是额外申请应用权限和用户授权；保留适配器边界。界面也可导出成片走官方创作中心。
- **生效。** 将本地提交合入实际安装分支，完整退出并重开 DSH 以加载队列、页面和生物钟提示。QQ 桥接可重开以加载叙事简报的原创视频映射。角色级作品日志也可由插件的记忆卡和向量维护直接读取。
- **回滚。** 调回「只存本地草稿」会暂停新的外发，已提交稿继续只读查询。关视频创作会暂停后台视频任务；数据库、媒体和已确认回执留存。回退插件时保留数据库，避免将结果未明的稿件重新发出。

## 验证

- `npm run test:video` 含 70 项 FFmpeg 本地成片断言和 8 组投稿接口测试。模拟分片失败后的断点恢复、回执丢失、按媒体标识核对、审核后只记一条作品与一次报备、角色/稿件包不符、改分区、素材授权、隐私与地址隔离。
- B 站现有发布、会话归组、插件配置、客户端契约和记忆卡专项通过。全量审计 134/157，与第二阶段基线失败集合相同。桥接回归受本地监听限制，两项旧 B 站测试依赖实际桥接状态和本地路径。
- 本次使用临时 DSH_HOME 和假接口，没有实际投稿或发通知。鱼姬账号上的网页协议、创作声明回读与真实审核仍待首稿验证。
