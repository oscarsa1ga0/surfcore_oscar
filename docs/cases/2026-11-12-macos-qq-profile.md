# NapCat 和 SurfCore 显示 QQ 旧资料

NapCat 4.18.42 保留了登录时的昵称，导致 WebUI 基础信息和 SurfCore 的自我身份记录显示旧值。与此同时，同一个账号的 `get_stranger_info(no_cache=true)` 已返回新昵称。看自己形象的 MCP 工具原本读取项目内置图片，因此也无法告诉角色她现在使用的 QQ 头像。

SurfCore 通过 OneBot 连接时获取登录帐号，连接后以及每分钟在线探活时，以 `get_stranger_info` 刷新当前帐号的昵称。只使用与登录账号匹配的资料，失败时保留最后一次有效昵称。QQ 自我身份提示和 B 站侧使用的身份记录会随之更新。外接 OneBot 的 `qq_get_self_image` 从 QQ 头像服务读取当前登录帐号的图像，用已有下载限制检查，再把图像和来源交给模型。头像下载失败会提示原因，原有本地网关继续提供其角色形象。

只重登 NapCat 可以重新加载其登录资料，但每次改名都重登会中断聊天，且无法让原来的看图工具读取 QQ 头像。将同步接在既有探活和工具上可以直接让角色取到资料。启用本次代码只需重启 QQ 桥接。回退时恢复本次代码快照再重启桥接。

NapCat 经 `set_restart` 重启，用户重新登录后，OneBot 和面板均显示新昵称，桥接已重连。运行中的看图工具实测返回更换后的 640×640 JPEG。面板仍显示企鹅，它使用 NapCat 登录资料提供的 `avatarUrl`，字段缺失时请求 QQ 头像服务的另一种尺寸。尚未确认面板取到旧图的具体原因。昵称、头像和原有图片读取专项用例通过，桥接回归通过，预设契约 8 项通过。全量审计 150/156，与改动前相同的 6 个 macOS 路径、Windows 工具/换行和发行清单用例未通过。

**发布交接**  
`feat/macos-qq`，建议 patch。变更范围为桥接身份刷新、头像工具和 QQ 预设用语。保留已有工具参数，新增头像来源字段及可操作错误提示。专项和实机头像通过，全量审计仍有环境基线失败，未发布。
