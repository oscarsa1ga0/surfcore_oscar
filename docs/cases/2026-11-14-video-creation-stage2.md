# 视频创作阶段二：混剪和自主审片

## 现象

第一阶段已有自述片出片引擎、项目数据库、Chrome/DSH 设置页接口及恢复测试。对 `feat/video-creation@499f246` 复跑 41 项 fixture 全过，包含真实 FFmpeg 的 H.264/AAC、中文 SRT、预览 Range 和中断恢复。旁白用本地假声合成。

旧实现的分镜、旁白放在各版本目录，改一个镜头会丢掉未修改部分的缓存复用。审片状态缺少成片和当前版本校验，旧版能误改项目状态。B 站唤醒开关已有配置字段，但未接创作提示。资源配置中的部分上限还未接执行器。

## 完整逻辑

- **链路。** B 站生物钟在两个功能开关打开时告诉鱼姬可以续剪。鱼姬走原有 `video-project` CLI，管理者在 DSH 设置页登记或撤销素材。命令写入当前角色库，再由既有 worker 渲染。设置页和 CLI 从同一个库取预览版本。审批入口仍按第三阶段语义返回 501。
- **机制。** 计划用素材 ID、区间和有限的转场枚举。剪辑镜头归一化后混音。内容摘要覆盖画面、时码、字幕与原声，未改工件跨版本命中。新版本落盘使用独立暂存和工件记录批次。审片用当前版本号检查，搁置取消该版本任务；运行中的任务失去 fence 后不可完成。角色页写素材时比对角色 ID 和 epoch。隐私文本在调用 TTS 前检查，普通图片/视频像素中的私密内容需要素材登记时人工识别。
- **影响面。** DSH 插件、B 站工具 CLI 和角色视频数据库三处共同读写。文件留在角色数据目录，授权撤销保留历史文件。云 TTS 沿用现有音色配置，根据实际调用计字数。
- **取舍。** 采用现有 SQLite 库、结构化计划和 FFmpeg 稳定的滤镜模板，局部可回滚。接完整 NLE 会新增一个编辑运行时、工程导入和权限管理面，成本更高。淡黑转场不改变整体时间轴，跨镜头重叠可按实际需求后续扩展。
- **生效。** 将本分支合入当前安装分支后重开 DSH；CLI 会在下一次调用读到新版本。管理端的分区、AI 声明、真实投稿和审核回读仍属于第三阶段。
- **回滚。** 关闭视频创作开关，保留素材、视频数据库和所有版本。退回阶段一插件后可读已有产物，新字段项目须使用阶段二及后续版本重新渲染。

## 验证

- 运行 `npm run test:video`（测试运行时依赖 FFmpeg、FFprobe、Pillow 和中文字体）。70 项通过，覆盖混剪实际出片、音效/音乐/原声、镜头缩短、试听、版本复用、授权撤销、旧审片拒绝、额度、停用、API 路径和恢复。
- B 站发布兼容、B 站工作区、插件 B 站自动化、管理配置 API、客户端契约与 B 站管理员提示均通过。
- 本机全量 `test:audit` 有原有失败。改后 134/157，干净基线 `499f246` 同环境 133/157，改后的 23 项失败都能在基线复现。常见失败包括 loopback `listen EPERM`、Windows 命令缺失/CRLF 及隔离副本无本地配置。隔离副本未使用私有线上配置。未做 DSH 图形界面和真实角色音色的人工验收。

## 发布交接

建议 minor。改动覆盖 `plugins/surfcore/lib/video/`、视频 CLI、插件管理 API/设置页及 B 站唤醒提示。计划 schema 保持 v1 并添加可选字段，工件和项目状态兼容阶段一。权限/路径/版本/额度失败有代码和下一步，测试覆盖真实 FFmpeg 和管理 API fixture。全量审计受干净基线既有失败影响，待合并前在目标环境跑绿。发布前还需确认 DSH 实际会话能打开关键帧及真实音色试听。详见本案例。
