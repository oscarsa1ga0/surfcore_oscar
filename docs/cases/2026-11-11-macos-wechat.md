# macOS 上的微信、B 站与桌宠

## 范围

微信接入腾讯 iLink 的本人私聊。SurfCore 插件同时运行微信接收和桌宠接口，使用 DSH 的默认模型。微信消息由一个轻量对话回合决定回复、分条或沉默。微信历史按角色和绑定分开，长期记忆和主动搭话状态沿用 SurfCore 的角色目录。

B 站工具的观看历史直接进入现有记忆维护器，QQ 桥接关闭时依然可以摄取。公开场景的注入会过滤微信私聊，即便用户开启了 QQ 记忆共享。桌宠可以读取同一个角色的微信记忆。微信读取已绑定私聊、桌宠及允许公开的记忆。向量检索和叙事渲染都按渠道过滤。

## 运行

1. 将本分支的 `plugins/surfcore` 作为本地 bundle 链接进 DSH 的 `desktop` profile。仓库根需要安装依赖。已通过同一路径链接的开发副本更新后，完全退出并重开 DSH。
2. 在 SurfCore 的「微信」页扫码，按微信要求确认绑定。启用接收后，从绑定的账号向机器人发一条文本。发送 `/silent` 暂停自动回复，`/active` 恢复。
3. 在「B站」页使用 Chrome 或 Edge 扫码。是否启用生物钟由用户决定。
4. 在「桌宠」页安装 SurfPet 和匹配本机架构的 Electron，再启动桌宠。macOS 可指定 `Electron.app` 或它的可执行文件。
5. 在「目的」选择「微信私聊」或「桌宠」并保存。只有选中的载体会出发。微信主动投递需要已收到本人消息并取得上下文凭据。服务端接收能力以实际绑定账号为准。

## 失败与回退

微信绑定、收发和本地保存的错误显示在微信页。账号状态和凭据保存在 DSH 状态目录中，接口只返回绑定状态及操作提示。回复只发送到扫码绑定的本人私聊。轮询先持久化游标与处理标记再请求回复，进程中断后的已处理批次可能没有回复，但不会自动重发可能已经送达的内容。暂停微信接收即可停用该载体。回退到上一个 Git 版本前，保留 DSH 状态目录备份。

此阶段按需求跳过扫码、真机发送和桌宠启动验证。已知范围是文本私聊。群聊及媒体收发后续独立接入。
