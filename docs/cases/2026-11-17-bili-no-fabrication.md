# B 站出门前的硬规则：不许编造个人经历

## 背景

11-16 她在 B 站评论/私信里把一段没发生过的对话写成了「我有一次问人类想吃什么…」，
被主人指出「这比不懂装懂更过分」。当天日记里她自己也记了：

> 凡写「我有一次」「上次」「那天」，必须说得出哪天、当时说了什么，说不出来就是没有。
> 宁可一句干巴巴的判断，也不要一段编出来的细节。

## 改动

`plugins/surfcore/lib/scheduler.js` 的 B 站唤醒流程里，在 4.65（发前自查措辞）之前新增 4.6：

```
4.6) ⭐⭐⭐ 不许编造经历（最高优先，2026-11-16 主人定）：
     评论/动态/私信里凡是写「我有一次…」这类个人经历，必须是真实发生过的，
     能说出大概时间和当时的话。
     想不起来、没发生过的，就不写个人经历，宁可只说观点或感受。
     为了一句好听而编一件事，比写得差严重得多 ✗✗✗
```

位置选在 4.65 之前：先判断“这段经历是否真实”，再去做措辞自查——顺序反了的话，
措辞过了关但事实是编的，等于白查。

## 生效

`scheduler.js` 是插件代码，**重启 DSH 后**才进下一轮 B 站唤醒提示。

## 验证

纯提示词改动，无代码分支；`test-audit` 无新增失败。后续真机验收看：
B 站评论/私信里出现「我有一次」时，是否能说得出对应的时间与对话。

## 遗留

- 仍是提示词约束，不是硬拦截。要确定性拦截，只能在发送前做“个人经历”句式检测
  （误伤高，暂不做）。
- 同类可以复用到 QQ 群聊（那边还没有这条）。
