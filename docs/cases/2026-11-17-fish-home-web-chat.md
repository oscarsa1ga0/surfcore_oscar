# 鱼姬之家 v0.1

基于本机安装线 `feat/macos-qq@1509ff4`，在独立分支 `feat/web-chat` 实现。

## 用户入口

1. 将功能分支合入本机实际安装分支后，完全退出并重开 DSH。若试用期间保留 QQ，也要从 SurfCore 重启一次 QQ 桥接，加载新版的投递分流。
2. 在 DSH 中打开「设置 → SurfCore → 鱼姬之家」。点击「启用本机聊天」，然后点「打开并配对」。配对后可收藏 http://127.0.0.1:17632/。
3. 先发文字、图片和 GIF，再连续发几条。确认回复逐段出现、工具审批可操作、刷新后历史可以恢复。若系统阻止自动打开，可点设置页给出的一次性配对链接。
4. 试用成功后，在同一页点「切换到网页私聊投递」，再关掉浏览器。从「目的 → 立即试一次」投递网页主动消息。重新打开网页查看收件；随后分别确认 B 站和日记任务运行。确认全部通过后，可以按实际依赖停止 QQ 桥接。

「切回 QQ 私聊投递」可恢复 QQ 的主动投递。网页和已保存的记录仍可打开，也可以再停用本机聊天。网页从启用后开始累计聊天，长期记忆继续使用原角色的卡。旧 QQ 聊天可以在原渠道查看。语音和像素小屋留待后续。

## 完整逻辑

- **链路**。浏览器走固定回环 HTTP 和 SSE。Gateway 和 B 站、日记都在 DSH 插件宿主里，消息通过同一 `role-dispatch` 调用 `sessionController.prompt`，关联独立的角色私聊会话。工具审批和提问接 DSH 的原生 waterfall，日记工具仍由宿主注册。网页发送图片工具只在本角色的网页回合有效，文件限制在网页会话工作目录。
- **机制**。SQLite 先原子保存用户消息、附件和任务，再提交 DSH。SSE 使用消息游标补投持久记录。实时文本来自 `agent/assistant-stream` 的 `text-delta`，最终文本和是否完成由持久化 session 事件确认。若宿主中断，按原请求 ID 查回合记录。无法确认结果时显示失败和核对提示，由用户决定是否发起新回合。
- **影响面**。Web 默认关闭，启用与切换主投递是两个独立操作。按角色隔离聊天数据。Web 私聊记忆使用独立可见范围，主人网页会话能读自己的 QQ 私聊与日记工具，B 站和其他 QQ 会话的记忆提示不包含 Web 私聊。当前记忆模式若启用向量检索，网页沿用已配置服务和同样的读写条件。语音、QQ 群和 B 站公开活动各走原路径。B 站主人通知若原先配置成 QQ，会随主动载体切换至网页；Webhook 等其他现有配置继续走原目标。
- **取舍**。Gateway 随宿主启动可以直接用宿主会话、调度、工具和角色上下文，代价是宿主退出期间网页离线。独立进程可以继续提供只读历史，但要接两段生命周期、跨进程鉴权和调度恢复。首版使用随宿主启动的 Gateway，配合固定端口和重连。Mac 可运行且 DSH 启动时，关浏览器仍可积累收件。
- **生效**。合入后重启 DSH，QQ 桥接若继续运行也重启一次。SQLite、工作目录、浏览器会话和 CLI 通知令牌位于 `~/.dsh/surfcore/web-chat/`。需要备份时，在 DSH 停止后复制目录。
- **失败反馈**。端口冲突显示在设置页；不支持的图片、重复请求冲突和过期审批返回带 `code`、`hint` 的错误；可核对的失败显示在相应消息旁。动图仍可浏览，模型侧抽帧失败时会显示降级说明。
- **验证与回滚**。运行 `node plugins/surfcore/scripts/test-web-chat.mjs` 复现配对、发图、顺序、流式、审批、重启回读、主动投递及私密记忆可见范围。夹具使用真实 SurfCore 调度器、真实 SQLite 以及按本机 DSH 协议构造的事件。全量审计 135/162，原基线 134/161，失败脚本集合相同。桥接回归在此执行环境绑定本机端口时返回 `EPERM`，基线同样失败。真实浏览器、模型工具审批、GIF 抽帧以及停止 QQ 后的 B 站和日记运行仍需按上面步骤在真机确认。

## 发布交接

`feat/web-chat` 以 `feat/macos-qq@1509ff4` 为起点，新增 Web 私聊模块、SurfCore 设置入口、主人通知迁移、私聊记忆范围及专项夹具。接口层新增本机 HTTP/SSE，旧客户端继续使用原接口。建议作为新功能随 minor 评估。专项通过，全量审计无新增失败脚本，真实宿主和浏览器待验收。先在本机功能线试用，再决定切换 QQ。
