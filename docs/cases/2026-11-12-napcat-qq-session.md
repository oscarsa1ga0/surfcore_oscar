# NapCat 报在线时 QQ 资料和好友列表失效

## 现场

NapCat 4.18.42 的 HTTP / WebSocket 仍可访问时，QQ 内核的资料查询曾超时或返回 `coreInfo` 为空，好友列表变空，新的私聊未进桥接。NapCat 容器在 13:43:09 与 14:44:29 收到显式重启请求。macOS 电源日志显示 14:20:09 合盖、14:27:16 唤醒，交接记录中的第一次资料超时在 14:28:26。11:42:01 合盖至 11:51:54 唤醒也与一次消息接收中断相邻。睡眠是有时间证据的触发线索，QQ 会话失效原因仍待对照验证。

13:29:28 的「工具已发送消息，跳过自动转发」是回合结束摘要。工具日志显示该会话 13:21 至 13:23 有八次真实发送成功，13:29 结束前只等消息和调整唤醒配置。13:29 的摘要不能当成当时又发送了一条消息的回执。

## 完整逻辑

1. QQ 内核 → NapCat OneBot → SurfCore 桥接 → DSH。桥接本来每分钟轮询 HTTP 状态并刷新外接 OneBot 的资料，面板读取桥接 `/api/status`。继续用真实资料查询，并在既往成功、连续两次失败后以好友列表成功返回空数组作交叉核对。
2. 故障快照提供 `sessionFailure.code/error/hint`，独立记录 OneBot 的 `online`。资料恢复或连接重建时重新判断。浏览器端在概览和 QQ 页展示告警。手动发起或早安遇到空名单时核对资料，证据吻合时报网关会话异常。自动发起按原调度稍后复核，真正的非好友仍按原名单拦截。
3. 自动重启对空好友号和短暂查询抖动都可能造成停机。采用 NapCat 自带的「快速登录QQ」配置恢复会话，桥接提供异常提示。已通过 WebUI 保存账号，等待实际离线确认快捷票据可用。腾讯要求重新登录时由用户完成验证。
4. 运行时改动只落在外接 OneBot 的状态探测和主动好友校验。观察脚本每分钟只读状态、好友、实时资料和最近消息的时间戳。生效需重启 SurfCore 桥接，NapCat 会话继续运行。还原本次修改的桥接和前端文件、重启桥接并重开设置页即可回退。快速登录账号可在原位置清空并保存。
