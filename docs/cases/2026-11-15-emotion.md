# 鱼姬的跨平台情绪

SurfCore 的目的引擎会保留某个念头或主动互动的情绪。角色需要在普通对话和不同平台之间延续短期的心情。功能分支基于 `feat/macos-qq@9d46d11`。九维基线和部分变化规则改编自 Fish Heart，授权见仓库 LICENSE。 [Fish Heart 源码](https://github.com/Vivy33/astrbot_plugin_fish_heart/tree/7147504ca1bb38ebdf891808a017292e481ce38e)

## 完整逻辑

- `src/emotion.js` 实现九维、自然回落、重复事件折减、维度耦合、期待、五档和按对象修复。两次明确修复可以让严重冲突缓下来。连续无人回应只改变期待。事件文本只在来源进程内分类。
- `src/emotion-events.js` 将 QQ 桥接和 B 站 CLI 的归一化事件原子写进角色收件目录。宿主 `plugins/surfcore/lib/emotion.js` 是情绪状态唯一写者。状态和已见事件一起原子提交，再清理已消费文件。事件只有来源、类别、时间和哈希标识。角色 ID 和 epoch 拒绝切换后的迟到事件。角色切回后恢复它自己的状态。
- QQ 在准入和命令过滤后记录新互动。群聊明确指向鱼姬的对话影响对应对象，普通群聊只轻微影响社交和疲惫。群聊快照只有一个明确的潜在对象时才给出定向提示，工具继续读消息后的步骤使用通用心境。
- B 站的深看、评分、私信、评论、直播互动和已发布作品能更新心境。QQ 空间的真实发布及新评论、视频的渲染和投稿结果同样可以更新。日记工具可传 `afterWriting` 记录写作引起的变化，一篇日记中的同类感受只记一次。
- DSH 通过作用域明确的 `systemPrompt.context()` 在模型实际准备请求时取最新的定性状态。变化后的 DSH 动态快照可进入会话历史，新的快照语义上覆盖旧的。直接调用 LLM 的桌宠走共用组装逻辑。旧宿主在 SurfCore 管理入口使用单轮追加。原生 DSH 工作区支持需有动态上下文服务。
- SurfCore 设置的「情绪」页显示九维、期待、冲突档位和近期变化。原生 DSH 工作区可填绝对路径显式绑定当前角色。公开场景只得到通用心境，定向冲突和等待限定为对应会话。目的引擎只读心境并有限调权，调度、冷却、上限和权限仍由原机制负责。

## 取舍、生效与回滚

独立运行原插件会引入第二套主动搭话、历史和进程，部署及回退都涉及多边。跨进程分别写角色状态的接线较短，但无法避免并发丢更新。此次选宿主单写，每个入口只提供事件或读取状态。

代码合入实际安装分支后需要重开 DSH 与 QQ 桥接。可在情绪页关闭功能或关闭单一来源，也可回退代码。原有角色卡、日记、记忆和会话文件由原系统维护。情绪 API 在读写失败和角色已切换时返回错误与下一步提示，角色对话可继续。当写入状态无法读取时，情绪页显示诊断。

## 验证

- `node scripts/test-emotion.mjs` 覆盖九维、分类、修复、对象隔离、期待、落盘去重、角色切换、关闭单一来源和日记隐私。
- `node plugins/surfcore/scripts/test-platform-start-host.mjs` 覆盖情绪设置 API、普通会话的隔离、原生角色工作区和 QQ 投递后才读取的心境。
- `node scripts/test-audit.mjs` 在开发沙箱 135/159，干净基线 134/158，失败脚本集合相同。单独的桥接回归需要绑定本地端口，开发沙箱拒绝。
- 真机待验收。QQ 发送互怼、重责和道歉，看 B 站占用队列期间发生的事件是否只计一次。在 B 站深看和评分后检查 QQ 心境。日记追加明确的 `afterWriting` 后刷新情绪页。

## 发布交接

`feat/emotion` 基于 `feat/macos-qq@9d46d11`，用户可见功能按 minor 交接。提供情绪页、角色范围内事件持久化、动态上下文和目的权重。QQ 调度的可选元数据向后兼容，宿主不会把它传入 DSH 提示接口。设置和读写失败提示见上。待合入安装分支重启两进程并真机验收。
