# 鱼姬的跨平台情绪

SurfCore 的目的引擎会保留某个念头或主动互动的情绪。角色需要在普通对话和不同平台之间延续短期的心情。功能分支基于 `feat/macos-qq@9d46d11`。九维基线和部分变化规则改编自 Fish Heart，授权见仓库 LICENSE。 [Fish Heart 源码](https://github.com/Vivy33/astrbot_plugin_fish_heart/tree/7147504ca1bb38ebdf891808a017292e481ce38e)

## 完整逻辑

- `src/emotion.js` 实现九维、自然回落、重复事件折减、维度耦合、期待、五档和按对象修复。两次明确修复可以让严重冲突缓下来。连续无人回应只改变期待。事件文本只在来源进程内分类。
- `src/emotion-events.js` 将 QQ 桥接和 B 站 CLI 的归一化事件原子写进角色收件目录。宿主 `plugins/surfcore/lib/emotion.js` 是情绪状态唯一写者。状态和已见事件一起原子提交，再清理已消费文件。事件只有来源、类别、时间和哈希标识。角色 ID 和 epoch 拒绝切换后的迟到事件。角色切回后恢复它自己的状态。
- QQ 在准入和命令过滤后记录新互动。群聊明确指向鱼姬的对话影响对应对象，普通群聊只轻微影响社交和疲惫。群聊快照只有一个明确的潜在对象时才给出定向提示，工具继续读消息后的步骤使用通用心境。
- B 站、QQ 空间、视频创作和日记分别按实际成功的动作或观察到的结果上报情绪。各入口的触发条件见下表。
- DSH 通过作用域明确的 `systemPrompt.context()` 在模型实际准备请求时取最新的定性状态。变化后的 DSH 动态快照可进入会话历史，新的快照语义上覆盖旧的。直接调用 LLM 的桌宠走共用组装逻辑。旧宿主在 SurfCore 管理入口使用单轮追加。原生 DSH 工作区支持需有动态上下文服务。
- SurfCore 设置的「情绪」页显示九维、期待、冲突档位和近期变化。原生 DSH 工作区可填绝对路径显式绑定当前角色。公开场景只得到通用心境，定向冲突和等待限定为对应会话。目的引擎只读心境并有限调权，调度、冷却、上限和权限仍由原机制负责。

## B 站逛完后心境没有变化

本机 11 月 15 日 17:31 和 17:34 的评论已经写进 B 站成功账本，情绪状态没有 B 站事件。原实现监听收到的评论，`comment --go` 的成功分支只有评论记账。浏览推荐和视频浅读也缺少情绪上报，普通评分低于 16 分时没有事件。

| 场景 | 已接入的触发条件 |
| --- | --- |
| B 站浏览和观看 | `feed` 和 `gamefeed` 返回非空候选时，每半小时窗口记一次浏览。`debrief --no-frames` 和 `video` 按浅看记。成功抽帧的 `debrief` 和 `watch-video` 按深入观看记。历史回填和仅预览列表跳过。 |
| B 站评分 | 评分持久化后按视频和日期去重。评分达到 16 分会增加喜悦。其余有效评分记录为评分事件。 |
| B 站私信和评论 | 调度器发现符合规则的新私信或评论，以及 CLI 确认发送成功的私信和评论。评论按 B 站返回的评论 ID 去重，私信使用平台回执。 |
| B 站直播互动及已发布作品 | 直播监听命中、弹幕成功发出以及动态或专栏确认发布。动态 ID 在文字、图文及上层命令之间共用。 |
| QQ 空间 | 发布成功且取得说说 ID，或者定时轮询发现她自己的说说新增评论。初次轮询建立基线。 |
| 视频创作 | 渲染成功、终止性渲染失败、投稿确认受理、确认公开和审核驳回。结果未知时等对账确认。 |
| 日记 | `diary_write` 或有正文变更的 `diary_edit` 成功，并带有效 `afterWriting`。同一篇日记的同类感受只记一次。 |

以各 CLI 的真实回执和观看记录为依据，沿用角色文件的情绪收件目录与宿主单写。另一种做法是在 B 站回合结束时统一加数值，成本更低，但无法区分预览、失败或实际互动，也无法覆盖手动运行命令。使用已有回执可以独立回退各入口，也能保留不同操作的原因。此前的评论没有情绪回执，此次补线从新操作开始记录。

## QQ 私聊的疲惫涨得太快

QQ 桥接按收到的消息上报，宿主按事件计算。用户把一句话拆成多个气泡时，每个气泡都可能累加疲惫，既有的重复折减不足以抵消短时间内的消息数量。

宿主在 `src/emotion.js` 将普通 QQ 私聊的每条基础疲惫从 0.6 调为 0.12，再沿用重复折减和 0–100 的边界。QQ 桥接继续通过原有事件接口投递，情绪页和各角色上下文读取宿主结果。已有状态按原规则随时间回落。另一条路线是按对话回合合并消息，但需要定义连续对话的边界，并处理排队、取消和跨重启。当前调整只需改一个来源的疲惫增量，可单提交回退。

合入安装分支后完全退出并重开 DSH，查看情绪页「最近的情绪变化」。低于 0.05 的单条变化仍计入总值，列表按一位小数显示。专项测试模拟两分钟内收到 20 条私聊，校验疲惫从 44 起步低于 45，社交和喜悦继续上涨，被请教仍按原规则计算。状态文件读写错误仍通过情绪页的既有诊断呈现。

发布交接建议 patch，分支 `fix/qq-private-fatigue`，基于安装分支 `cd7295b`。核心调整在 `src/emotion.js`，回归验证在 `scripts/test-emotion.mjs`，事件和状态格式兼容。情绪专项 11 项和宿主接线测试通过。全量审计与安装分支基线同为 136/159，失败脚本一致。真机验收以用户之后的正常 QQ 私聊为准。

## 降低 QQ 群聊情绪权重

QQ 桥接对未直接指向鱼姬的群消息按每群每分钟记录一次群聊气氛。持续活跃的群仍会推高共享的社交和疲惫。宿主在 `src/emotion.js` 将群聊气氛由 25% 降至 8%，主人直接互动由 80% 降至 40%，其他群友直接互动由 55% 降至 25%。群聊中受到责怪时也使用对应权重。

延长桥接采样间隔只能减轻背景累积，并且会减少采样。降低宿主的权重可以保留事件节奏，同时控制直接互动的幅度。变更作用于宿主消费的 QQ 群聊事件，复用情绪页和上下文的已有状态接口。变化小于 0.05 时可能不显示在近期列表中，仍计入数值。情绪页继续报告状态读写错误。

发布交接建议 patch，分支 `fix/qq-group-emotion-weight`，基于本机安装分支 `a8340a4`。情绪专项 12 项和宿主测试通过，覆盖持续群聊气氛、不同发言者直接互动和冲突按对象隔离。首次全量审计中 embedding 包的卸载夹具偶发失败，单独复测 4 项通过，全量重跑与基线同为 136/159，失败脚本一致。合入后完全退出并重开 DSH，以后续群聊验证实际体感。可单提交回退。

## 首次自评

情绪页点「请她自评」后，SurfCore 使用 DSH 的默认模型，在当前角色的人格卡及近期记忆基础上生成九个 0–100 的数值。这次调用计入「其他」模型额度。自评成功前，各入口只读角色原有上下文。自评开始后出现的新事件进入收件目录，成功落盘后按发生时间应用到初值。已积累情绪的角色继续原状态。模型输出缺项或越界时可重试，切换角色后会丢弃旧结果。

选择设置页主动触发可以让用户确定启用时点，且同一角色只调用一次。若改成每个新角色第一次收到消息自动触发，QQ 或 B 站首轮会等待额外的模型回合，失败和模型额度不足也会影响首次使用体验。

## 取舍、生效与回滚

独立运行原插件会引入第二套主动搭话、历史和进程，部署及回退都涉及多边。跨进程分别写角色状态的接线较短，但无法避免并发丢更新。此次选宿主单写，每个入口只提供事件或读取状态。

代码合入实际安装分支后需要重开 DSH 与 QQ 桥接。可在情绪页关闭功能或关闭单一来源，也可回退代码。原有角色卡、日记、记忆和会话文件由原系统维护。情绪 API 在读写失败和角色已切换时返回错误与下一步提示，角色对话可继续。当写入状态无法读取时，情绪页显示诊断。
