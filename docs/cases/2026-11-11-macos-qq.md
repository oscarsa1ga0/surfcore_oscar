# macOS QQ 安装指南

## 安装

1. 在 [LLBot 快速安装](https://luckylillia.com/guide/choice_install) 选择 macOS，安装适合本机架构的版本，用机器人的 QQ 账号登录。
2. 在 [LLBot 配置](https://luckylillia.com/guide/config) 启用 OneBot 11 的 HTTP API 和正向 WebSocket。两项都使用回环地址 `127.0.0.1`，消息格式选数组，设置访问 token。WebUI 如果与 DSH 端口冲突，可以改成 3081。
3. 彻底退出 DSH。从此分支的仓库根执行下列命令，安装依赖并注册 DSH 桌面插件和 QQ 工具。已有 Node.js 22.13 及以上版本和 npm 时，依赖安装也可以用 `npm ci`。

   ```sh
   surfcore_dsh_runtime='/Applications/DeepSeek Harness.app/Contents/Resources/runtime/primary-runtime/dependencies'
   PATH="$surfcore_dsh_runtime/node/bin:$PATH" "$surfcore_dsh_runtime/node/bin/node" "$surfcore_dsh_runtime/pnpm/bin/pnpm.cjs" install --no-frozen-lockfile --lockfile=false
   QQ_BRIDGE_SKIP_DSH_INSTALL=1 "$surfcore_dsh_runtime/node/bin/node" scripts/setup-dsh.mjs desktop
   ```

4. 重开 DSH，在「设置 → SurfCore → QQ」的「QQ · OneBot 11」填写连接参数并保存，然后点「测试 HTTP 连接」。常用参数如下，以 LLBot 实际配置为准。

   | 字段 | 常用值 |
   | --- | --- |
   | HTTP API | `http://127.0.0.1:3000` |
   | 正向 WebSocket | `ws://127.0.0.1:3001` |
   | HTTP token | LLBot HTTP 服务的 token |
   | WebSocket token | LLBot 正向 WebSocket 的 token，两者相同时可留空 |

5. 在「QQ」页填主人 QQ 号和私聊或群白名单，打开「启动 QQ」并保存。从「概览」启动 QQ。看到「QQ WebSocket 已连接」后，用白名单中的账号发一条消息，核对 DSH 会话和 QQ 回复。

## 实现和范围

Windows 版由 SurfCore 发现并启动 SnowLuma。macOS 的 SnowLuma 启动器和账号配置不可用，由已登录的 LLBot 提供同一套 OneBot 11 接口。HTTP 使用自己配置的地址和 token，正向 WebSocket 支持单独的 token。接收、白名单、回复和审计仍由同一个 SurfCore QQ 桥接负责，目的、B 站、记忆和身份对齐使用原版的渠道。

使用原有桥接接入兼容的 QQ 网关，改动集中在连接、平台启动与设置。另写一套 QQ 桥接需要重做会话、权限和回复策略。Mac 的 B 站扫码可启动 Chrome 或 Edge，桌宠可安装本机架构的 Electron。随 Windows 发布的本地语音和向量运行包仍需各自的 macOS 运行环境，QQ 基础收发可独立运行。

## 验证和回退

- `node scripts/test-snowluma-conn.mjs` 模拟 HTTP 探测，核对 HTTP 与 WebSocket 各用自己的 token。实际 QQ 收发按安装步骤第 5 项验收。
- 修改网关连接参数后重启 QQ 桥接。切换回其他 SurfCore 工作树时，从该工作树重跑 `scripts/setup-dsh.mjs desktop`，再重新打开 DSH。各工作树的仓库根 `config.json` 是独立的。

## 发布交接

- 基线为 fork 的 `main` 提交 `0ce8580`。macOS 使用 LLBot，复用原版 SurfCore 的 QQ 桥接和角色体系。
- 使用者需要在 LLBot 登录并配置 HTTP 和正向 WebSocket，再重开 DSH。正式投递以实际 QQ 私聊和群聊测试为准。
