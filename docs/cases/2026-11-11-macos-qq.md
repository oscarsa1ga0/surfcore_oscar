# macOS QQ 接入

## 配置

1. 按 [LLBot 安装指南](https://luckylillia.com/guide/choice_install) 安装适合本机架构的版本，启动 LLBot，并用肥鱼的 QQ 账号登录。
2. 在 LLBot 中启用 OneBot 11 的 **HTTP API** 和 **正向 WebSocket**，监听地址填 `127.0.0.1`，消息格式用数组，为服务配置 token。若 LLBot 的 WebUI 默认端口 `3080` 与 DSH 冲突，可按 [LLBot 配置说明](https://luckylillia.com/guide/config) 修改 `webui.port`，例如改为 `3081`。
3. 打开 DSH「设置 → SurfCore → QQ → QQ · OneBot 11」，填以下四项并保存。HTTP 测试成功时会显示已登录账号的昵称。

   | SurfCore 字段 | 常用值 |
   | --- | --- |
   | HTTP API | `http://127.0.0.1:3000` |
   | 正向 WebSocket | `ws://127.0.0.1:3001` |
   | HTTP token | LLBot 的 HTTP 服务 token |
   | WebSocket token | LLBot 的 WebSocket 服务 token。两者相同时可留空 |

4. 在 SurfCore「诊断 → 一键安装（全部）」安装桥接依赖、注册 DSH 工具，然后完全退出并重开 DSH。诊断会显示每一步的结果。
5. 在「QQ」页填写主人的 QQ 号，添加允许回复的私聊或群，开启「启动 QQ」并保存。在「概览」启动 QQ 后，「QQ」页会显示 WebSocket 连接状态。

如果需要从终端准备依赖和 DSH 工具，进入已经链接到 DSH 的 SurfCore 仓库根目录运行以下命令。

```sh
dsh_runtime="/Applications/DeepSeek Harness.app/Contents/Resources/runtime/primary-runtime/dependencies"
PATH="$dsh_runtime/node/bin:$PATH" "$dsh_runtime/node/bin/node" "$dsh_runtime/pnpm/bin/pnpm.cjs" install --no-frozen-lockfile
QQ_BRIDGE_SKIP_DSH_INSTALL=1 "$dsh_runtime/node/bin/node" scripts/setup-dsh.mjs desktop
```

## 实现和范围

- 旧启动流程依赖 Windows 的 SnowLuma 启动器和账号配置。macOS 由 LLBot 提供 OneBot 11，HTTP 用于获取登录状态和调用 API，正向 WebSocket 接收消息和通知。SurfCore 从设置读取地址与 token，由原有 QQ 桥接连接并自动重连。
- QQ 私聊和群消息继续使用原有的 DSH 会话、白名单、回复规则与审计，和微信、B 站、桌宠使用同一个 SurfCore 当前角色。跨渠道记忆仍受各渠道的隐私和分享配置约束。
- 接入范围是 OneBot 11 通用能力。语音、表情收藏和富媒体等扩展取决于 LLBot 提供的 API。Windows 走原来的 SnowLuma 流程。
- 连接参数修改后重启 QQ 桥接。若要暂停，关闭「启动 QQ」并保存。回退代码时可还原本次提交，角色资料和记忆沿用原路径。
- 本次只做离线检查。实机验收时，先看「测试 HTTP 连接」和「QQ WebSocket 已连接」，再从白名单账号发一条私聊或群消息，确认 DSH 会话和回复都回到对应聊天。

## 网盘资源

资源按钮从本地读取可选的提取码。需要预填时，在仓库根的 `state/resources.local.json` 中配置 `quark`、`xunlei` 或 `voiceQuark`，键值均为对应的提取码。没有本地配置时，网盘页面仍可打开，可按页面提示输入。该文件由 Git 忽略。

## 发布交接

- 变更内容：macOS 版接入 OneBot 11 QQ 网关，复用 SurfCore QQ 桥接、角色与工具权限。
- 使用变化：LLBot 需要独立登录。首次配置后需重启 DSH。QQ 开关、白名单和已有会话配置继续生效。
- 验证范围：仅离线检查。发布前可用真实 QQ 账号验证登录、私聊和群聊收发。
