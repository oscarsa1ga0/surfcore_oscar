# NapCat 收藏表情报文件名太长

macOS 的外接网关使用 NapCat 4.18.42。真实 QQ 会话中，`qq_collect_sticker` 已能取得用户发来的橘猫图片，但 `add_custom_face` 对 `base64://…` 调用文件状态检查并返回 `ENAMETOOLONG`。在容器里已有缓存的同一张图可以用本地路径完成收藏。NapCat 返回 `result/isExist`，收藏编号需要从收藏列表回读。

收藏工具沿用会话令牌、白名单和限频。桥接从消息提取并验证图片，NapCat 通路使用 `upload_file_stream` 将图片暂存于容器内，核对文件长度和 SHA-256 后执行收藏。QQ 列表的图片摘要可用于查找已收藏的图及核对新增结果。NapCat 上工具提供的备注存在 SurfCore 的本地表情库，原 SnowLuma 通路继续使用其收藏接口。网关拒绝时不会将可能包含整张图片的错误参数透传给模型。收藏已受理但查不到记录时，工具会提示先核对列表再重试。

仅使用 NapCat 的原图缓存路径适用于这张图，其他表情可能没有现成路径。暂存已校验的字节可以复用现有看图通路，并限制临时文件寿命。回退时恢复改动前的桥接代码再重启桥接，已收藏的图仍在账号内。

真实测试将那张失败的图补入 QQ 收藏，用列表核对摘要匹配。单独测试在实际 NapCat 上传临时图成功。桥接重启后通过实际 MCP 收藏工具回读该条目并确认跳过重复添加。桥接端点夹具覆盖上传、收藏后回读、回读失败提示和重复请求。表情专项及桥接回归通过。全量审计 151/157，剩余 6 项为已有的平台及发行清单检查失败。前一轮的头像提示已同步到 QQ 预设源文件，预设产物契约通过。
