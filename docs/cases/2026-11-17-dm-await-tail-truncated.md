# dm-await 的输出被 tail 截断：人还在、消息没了

## 现象

和 `fans` / `comment-digest` 同一个毛病：她的命令固定带 `| tail -2`。

`dm-await` 原来的排版：

```
DM_HIT mid=353782040 name=oscarsaigao ts=1794825551 count=3 text=最后一条…
  [18:39] 第一条
  [18:40] 第二条
  [18:41] 第三条
```

- `tail -2` 之后只剩最后两条明细：**前一条消息直接丢了**；
- `--any` 模式下更糟：每个会话只有一行 `DM_HIT mid=… name=…`，被切掉就等于「谁找过她」都不知道了。

## 修法

`plugins/surfcore/tools/lib/dm-format.mjs`（新增，可单测）：

1. 每条明细自带「时间 + 发送人 + 正文 + 链接」：
   `[18:39:11] 主人：看看这个 → https://…`
2. 最后一行给结论：`共 N 条新私信：主人（3 条） ｜ 最新 18:41 ｜ 完整条目在上面，别用 tail 截断`
   —— 即使 `tail -1`，也知道有几条、谁发的、最新时间；
3. `--any` 模式同样处理（先一行总数，再逐条，最后结论）。

## 验证

- `scripts/test-dm-format.mjs`：明细含时间/发送人/正文/链接；结论含条数、发送人分组、最新时间、提示；空列表返回「新私信 0 条」；换行被压平。已登记进 `test-audit`。
- `test-dm-card-parse` 同步更新接线断言（改成走 `dmItemLine`）。
- `test-audit` 147/161，14 个既有失败不变。

## 遗留

- 和她所有「先汇总、再明细」的命令一样：真正的修复是**别用 tail**；这次只是让被截断时她至少知道「漏了」。
- 同类待查：`fans`（已修）、`comment-digest`（已修）、`dm-await`（本次）、`quota status`（记录在最后，天然安全）。
